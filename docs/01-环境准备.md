# 01 环境准备

> 目标：把一台**国内云服务器**准备成适合跑 ASF 挂卡的环境。
> 全程约 10 分钟。

## 1.1 服务器怎么选

| 项目 | 建议 | 说明 |
|------|------|------|
| 系统 | **Debian 12 / 13**（x86_64） | ASF 官方提供 linux-x64 自包含包，无需装 .NET |
| 内存 | 2G 起步，1G 必须配 swap | ASF 单实例约 100–150MB；但如果你还要跑 Steam 客户端（解锁成就等），**需要 4G** |
| CPU | 1 核够用 | 挂卡几乎不吃 CPU |
| 磁盘 | 10G+ | ASF 本体约 52MB，日志会慢慢涨 |
| 带宽 | **别买按流量计费的** | 挂卡流量不大，但下载/更新会吃掉流量包 |
| 机房 | 大陆机房可用（**登录走 CM 长连接，不是 443 网页**）| 实测腾讯云/阿里云大陆机器 CM 连通性良好 |

> ⚠️ 三类需要提前知道的坑：
> 1. **1.9G 内存跑「ASF + Steam 客户端」会非常吃紧**，会出现负载飙升、SSH 连不上（swap 抖动）
> 2. **跨云直连带宽可能极差**：实测腾讯云 → 阿里云直连只有 0.45MB/s，而两边公网各自有 13–28MB/s
> 3. 部分地区/机房对 Steam CM 的**部分 IP 段**有限制，建议部署前先跑 `scripts/diagnose-steam-net.sh`

## 1.2 换国内镜像源（加速）

```bash
# 腾讯云机器用腾讯内网源（最快）
sed -i 's|deb.debian.org|mirrors.cloud.tencent.com|g; s|security.debian.org|mirrors.cloud.tencent.com|g' \
  /etc/apt/sources.list /etc/apt/sources.list.d/*.sources 2>/dev/null

# 阿里云机器用阿里云内网源
# sed -i 's|deb.debian.org|mirrors.cloud.aliyuncs.com|g' /etc/apt/sources.list /etc/apt/sources.list.d/*.sources

apt-get update
```

Debian 12+ 用的是新格式 `/etc/apt/sources.list.d/debian.sources`（deb822），上面的 `sed` 同样适用。

## 1.3 安装基础依赖

```bash
apt-get install -y curl unzip python3 ca-certificates
```

### ⚠️ 必须装 libicu（否则 ASF 启动即崩溃）

ASF 依赖 ICU 库，缺它表现是 **启动瞬间 `SIGABRT` 退出**，日志里看不出明显原因。

```bash
# Debian 各版本包名不同（libicu72 / libicu76 ...），自动挑最新的
PKG=$(apt-cache search --names-only '^libicu[0-9]+$' | awk '{print $1}' | sort -V | tail -1)
echo "安装 $PKG"
apt-get install -y "$PKG"
```

验证：

```bash
ldd /opt/asf/ArchiSteamFarm 2>/dev/null | grep -i 'not found' || echo "依赖齐全"
```

## 1.4 配置 swap（小内存必做）

```bash
# 2G swap
fallocate -l 2G /swapfile || dd if=/dev/zero of=/swapfile bs=1M count=2048
chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
free -m
```

> 实测教训：1.9G 内存机器在内存吃满后会进入 **swap 抖动**，`load average` 能冲到 80+，
> 表现是 **SSH 都连不上**（不是服务挂了）。配 swap 只能兜底，根治要靠升内存 + 用 `MemoryMax` 限制进程。

## 1.5 目录与用户规划

| 用途 | 路径 |
|------|------|
| ASF 主程序 + 配置 | `/opt/asf`（配置在 `/opt/asf/config`）|
| 社区反代 | `/opt/steam-proxy` |
| 日志 | `journalctl -u asf`，以及 `/opt/asf/logs` |
| systemd 服务 | `/etc/systemd/system/asf.service`、`steam-proxy.service` |

ASF **不必**用独立用户运行（默认 root 也行），但如果要跑 Steam 客户端等 GUI 程序，建议：
**客户端用普通用户（如 `steam`）+ Xvfb，ASF 用 root**，两者互不影响。

## 1.6 时间同步（重要）

Steam 登录与令牌校验对时间敏感，确认时钟是同步的：

```bash
timedatectl          # 看 "System clock synchronized: yes"
apt-get install -y systemd-timesyncd && systemctl enable --now systemd-timesyncd
date -u              # 与 UTC 差几秒以内即可
```

> 实测遇到过：机器本地时间与真实时间差很多（`uptime` 与 HTTP `Date` 头对不上），
> 这种情况可能影响令牌/证书校验，先 NTP 对齐再排查其他问题。

## 1.7 防火墙

```bash
apt-get install -y ufw
ufw allow 22/tcp            # 先放行 SSH，别把自己关在外面
ufw enable
ufw status
```

之后的端口按需放行（ASF 的 IPC 端口**不建议**对公网开放，见 05 章）。

## 1.8 准备完成检查

```bash
echo "== 系统 ==" && cat /etc/os-release | grep PRETTY_NAME && uname -m
echo "== 资源 ==" && free -m | head -2 && nproc
echo "== 依赖 ==" && ldconfig -p | grep -c libicu && python3 --version
echo "== 网络 ==" && bash scripts/diagnose-steam-net.sh | head -20
```
