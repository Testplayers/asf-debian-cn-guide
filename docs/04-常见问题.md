# 04 常见问题 FAQ

> 全部来自实战踩坑，按类别索引。遇到问题先在这里搜关键字。

## A. 安装 / 下载类

### A1. GitHub 下载超时或极慢
**现象**：`curl: (28) Connection timed out`、几十 KB 后卡死。

**解决**：用镜像加速（多试几个），并开启断点续传：

```bash
for m in "https://ghfast.top/" "https://gh-proxy.com/" "https://ghproxy.net/"; do
  curl -fL --connect-timeout 10 --max-time 900 -C - -o ASF-linux-x64.zip \
    "${m}https://github.com/JustArchiNET/ArchiSteamFarm/releases/latest/download/ASF-linux-x64.zip" && break
done
```

### A2. 下载的文件是被截断的（大小不对）
**现象**：文件只有预期的一部分，`unzip -t` 报错。

**排查**：先确认「文件坏了」还是「解压工具太老」——用 python 校验：

```bash
ls -l ASF-linux-x64.zip                 # 与 release 页面大小对比
python3 -m zipfile -t ASF-linux-x64.zip # 通过 = 文件是好的
curl -sI <下载地址> | grep -i content-length   # 对比服务端真实大小
```

### A3. `unzip` 报 "overlapped components (possible zip bomb)"，但 python 校验证书通过
**原因**：Debian 的 `unzip 6.0` **不支持 zip64**（大于 4G 或启用 zip64 的包）。

**解决**：用 python3 解压（不要用 unzip）：

```bash
python3 -c "import zipfile; zipfile.ZipFile('ASF-linux-x64.zip').extractall('/opt/asf')"
```

### A4. ASF 启动瞬间崩溃（SIGABRT），日志看不出原因
**原因**：缺 **libicu**（ASF 的硬依赖）。

```bash
# 确认
systemctl status asf --no-pager | grep -i 'signal\|core-dump'
ldd /opt/asf/ArchiSteamFarm | grep -i 'not found'
# 安装（包名随 Debian 版本变）
PKG=$(apt-cache search --names-only '^libicu[0-9]+$' | awk '{print $1}' | sort -V | tail -1)
apt-get install -y "$PKG" && systemctl restart asf
```

### A5. 解压后目录里没有 `ArchiSteamFarm`
**原因**：ASF 的 zip **没有顶层目录**，你可能解到了错误的层级（比如 `/opt/asf/ASF-linux-x64/...`）。

```bash
find /opt/asf -maxdepth 2 -name 'ArchiSteamFarm'
# 直接解到目标目录即可: extractall('/opt/asf')
```

## B. 配置类

### B1. 配置解析失败：`expected number, got string`
**原因**：`UpdateChannel` 是**数字枚举**，写成 `"Stable"` 必失败。

**解决**：删掉该字段（默认即稳定版）：

```bash
python3 -c "
import json; p='/opt/asf/config/ASF.json'; d=json.load(open(p)); d.pop('UpdateChannel',None)
json.dump(d, open(p,'w'), indent=2, ensure_ascii=False); print('done')"
systemctl restart asf
```

### B2. 改了 ASF.json 里的监听地址，IPC 端口没变化
**原因**：IPC 监听地址**只在 `config/IPC.config`** 里生效。

```bash
cat /opt/asf/config/IPC.config     # {"Kestrel":{"Endpoints":{"HTTP":{"Url":"http://127.0.0.1:1242"}}}}
sed -i 's|http://127.0.0.1:1242|http://*:1242|' /opt/asf/config/IPC.config
systemctl restart asf && ss -tlnp | grep 1242
```

### B3. 外网打不开 IPC（`IP:1242`）
按顺序排查（三层）：

```bash
ss -tlnp | grep 1242                        # ① 是否只监听 127.0.0.1
ufw status | grep 1242                      # ② 防火墙是否放行
# ③ 云厂商安全组（控制台）是否放行 —— 云主机必须单独配置
```

> 建议：**不要**把 IPC 暴露公网，用 SSH 隧道：`ssh -L 1242:127.0.0.1:1242 root@IP`（详见 05 章）。

### B4. 加了机器人配置文件但没登录
检查清单：

```bash
ls -l /opt/asf/config/*.json                # 文件名 = 机器人名（区分大小写）
grep -H '"Enabled"' /opt/asf/config/*.json  # 必须是 true
journalctl -u asf -n 50 --no-pager | grep -iE 'bot|error|invalid'
```
常见错误：JSON 语法错（尾逗号）、字段名大小写错（`SteamLogin`）。

### B5. 服务器日志在本地终端显示乱码/报 GBK 错误
**原因**：Windows 终端默认 GBK，无法解码 UTF-8 日志。

**解决**（用 SSH 客户端/脚本时指定 UTF-8）：

```python
# Python 侧
import sys; sys.stdout.reconfigure(encoding="utf-8", errors="replace")
```
```powershell
# PowerShell 侧
[Console]::OutputEncoding = [Text.Encoding]::UTF8
```
另外注意：PowerShell 里写远程命令时 `$var`、`$(...)` 会被**本地**展开，容易出错 ——
复杂脚本建议**先上传文件再执行**，不要直接拼在 ssh 命令里。

## C. 网络类（重点）

### C1. ASF 显示在线，但一直不掉卡 ⭐最常见
见 [03 章](03-社区反代-steam-proxy.md)。判据：

```bash
journalctl -u asf -n 100 --no-pager | grep -iE 'badge|Request failed'
# 卡在 Checking first badge page... / Request failed = 社区被阻断
```

### C2. 反代搭好了，但 ASF 还是报证书/请求失败
**原因**：自签 CA 没进系统信任链，或证书缺少 SAN。

```bash
cp /opt/steam-proxy/cacert.crt /usr/local/share/ca-certificates/steam-proxy-ca.crt
update-ca-certificates
systemctl restart asf steam-proxy
# 验证（不要用 -k，要能通过校验）
curl -sS -o /dev/null -w '%{http_code}\n' https://steamcommunity.com/
```

### C3. 访问返回 `HTTP 000` 且 0.0x 秒就失败
**原因**（按概率）：
1. Caddy 没在监听那个端口：`ss -tlnp | grep 443`
2. **iptables 重定向指向了没人监听的端口**（`ExecStartPre` 静默失败导致）：

```bash
iptables -t nat -L OUTPUT -n --line-numbers
# 有 443→8443 但你没监听 8443 → 删掉规则，或改用「直接监听 443」方案
iptables -t nat -D OUTPUT -p tcp -d 127.0.0.1 --dport 443 -j REDIRECT --to-ports 8443
```

### C4. `api.steampowered.com` 用不了
**结论**：该域名在国内被 SNI 阻断，且**该上游要求必须带 SNI**（不带 SNI 时返回 `tlsv1 alert internal error`），
所以**无法用「上游写 IP」绕过**。

**替代**：用 Steam **客户端本地接口**（`ISteamUserStats` 等）或 `store.steampowered.com`（通常可直连）。

### C5. 反代原本正常，某天突然失效
**原因**：上游 Akamai 边缘 IP 变了。

```bash
bash scripts/diagnose-steam-net.sh        # 找可用 IP
UPSTREAM_IP=<新IP> bash scripts/setup-steam-proxy.sh && systemctl restart steam-proxy
```

### C6. 两台服务器之间传输文件极慢（但各自下载都很快）
**现象**：跨云（如腾讯云 → 阿里云）直连只有 ~0.45MB/s，而各自下载公网资源有 13–28MB/s。

**应对策略**：
1. **只传必要的小文件**（配置文件、登录态、数据库），程序/资源让目标机**自己下载**
2. 大目录可**并行多路 rsync** + `-z` 压缩（压缩对小体积文本/二进制有效）
3. 迁移 Steam 客户端这类大目录时，**优先只搬「登录态」**（`config/`、`userdata/`、`ssfn*`），程序文件用官方源重装
4. 记得在源机器装 `rsync`（Debian 最小化安装默认没有，会报 `bash: rsync: command not found`）

## D. 挂卡 / 账号类

### D1. 需要手机令牌验证码（`RequiredInput`）
```bash
journalctl -u asf -n 50 --no-pager | grep -iE '2FA|RequiredInput|two-factor'
```

| 方式 | 操作 |
|------|------|
| 控制台（`Headless:false`）| IPC → 输入 `2fa <机器人名> <5位验证码>` |
| 一劳永逸 | 导入 `.maFile`（MobileAuthenticator 插件），ASF 自动生成验证码 |
| 邮件验证 | 去邮箱收码，同样用 `2fa` 命令提交 |

> 验证码有时效（约 30 秒），收到要立刻提交。

### D2. 同一账号在两处登录，互相挤下线
Steam 同账号只允许一个客户端会话。

**正确顺序**：**先停旧机 → 再启动新机**

```bash
# 旧机
systemctl stop asf
# 新机
systemctl start asf
```

### D3. 换服务器后不想重新输令牌 ⭐
直接搬运登录凭据（**关键是 `*.db`**）：

```bash
# 旧机
tar czf /tmp/asf-state.tgz -C /opt/asf config plugins
# 新机
tar xzf /tmp/asf-state.tgz -C /opt/asf && systemctl restart asf
```

### D4. ASF 提示 "We don't have anything to farm on this account!"
**这是正常结果**：该账号可掉落的卡已全部挂完，ASF 会自动停止挂该账号。

### D5. 多账号容易被风控
- `LoginLimiterDelay` 调大（如 20–30 秒）
- **不要频繁重启 ASF**（每次重启都重新登录）
- 不要在同一台机器/IP 上跑大量账号（机房 IP 段是重点监控对象）
- 建议给每个账号保留稳定的登录会话（不要反复登出登入）

### D6. 怎么知道「挂满」了
```bash
journalctl -u asf --no-pager | grep -iE "nothing to farm|farming .*remaining"
# 或 IPC: !status / !farms
```

## E. 内存 / 性能类

### E1. 内存吃满、`load average` 飙升、SSH 都连不上
**原因**：内存不足 → swap 抖动（表现为 IO 等待，不是 CPU 高）。

```bash
free -m; uptime; ps -eo pid,rss,cmd --sort=-rss | head -8
```

**解决**（按性价比排序）：
1. 给服务加内存上限：systemd 单元里 `MemoryMax=600M`
2. 加 swap 兜底（`fallocate -l 2G /swapfile && mkswap /swapfile && swapon /swapfile`）
3. 减少并发实例数
4. **升级内存**（根治）

> 实测：ASF 单实例约 100–150MB；**Steam 客户端（含 CEF webhelper）约 1–1.2GB**，
> 1.7G 内存的机器同时跑「客户端 + ASF + 面板」会非常紧，建议 4G。

### E2. ASF 占用参考
| 项目 | 内存 |
|------|------|
| ASF 单实例（无机器人）| ~80–100MB |
| 每个在线机器人 | +10–30MB |
| 建议上限设置 | `MemoryMax=600M`（单实例）|

### E3. 服务反复重启
```bash
systemctl status asf --no-pager | head -15
journalctl -u asf -n 30 --no-pager | grep -iE 'oom|killed|signal'
```
关键字 `oom-kill` → 内存上限太低或被系统 OOM；调大 `MemoryMax` 或加 swap。

### E4. 日志把磁盘写满
```bash
journalctl --disk-usage
journalctl --vacuum-time=7d          # 只保留 7 天
# 限制总量（/etc/systemd/journald.conf）
# SystemMaxUse=200M
rm -rf /opt/asf/logs/*.log           # ASF 自身日志
```

### E5. systemd 的 `ExecStartPre` 明明失败了却不报错
**原因**：单元里以 `-` 开头的命令，失败会被忽略（`-` 表示"允许失败"）。

```ini
ExecStartPre=-/bin/bash -c "iptables ..."    # 失败不中断 → 也可能静默没生效
```
排查：手动执行同一条命令看报错（例如 `iptables: command not found`）。
